# 一、结论速览

| 敌种 | 决策 | 移动 | 避让 | 防卡死兜底 |
| --- | --- | --- | --- | --- |
| 哨兵 | AIPerception + StateTree | NavMesh 巡逻 + 限距 15m 追击 | RVO（引擎自带，调参） | 挪窝 |
| 掠食者 | AIPerception + StateTree | NavMesh 绕后接近 | RVO + 单局限 2 只 | 相位位移（设定允许） |
| 蜂群 | Hive 状态机（无 StateTree） | 蜂群算法直线追踪，**不走导航** | 自身就是分离算法 | 锚点拉回，天然不卡 |
| 裁决者 | AIPerception + StateTree（哨兵复制改造） | NavMesh 守点 + 破盾后追杀（30m leash） | RVO（次高优先级） | 挪窝（小半径） |
| 审计官 | 状态机（W6） | NavMesh 追击，复用同一移动层 | RVO | 瞬移 + 回舱重置 |

核心取舍（与死域 Rogue 同路）：**地面怪走 NavMesh，飞行群怪绕开整套寻路**——蜂群用蜂群算法（Boids），成本 O(n²) 但 n≤32 随便跑；单体卡死一律"检测 → 挪窝/瞬移"兜底，不做复杂路径修正。**能不写代码的地方全部用引擎现成机制**（StateTree 转换条件、MoveTo、RVO）。

> 故障体（C 区，本期范围外）：行为纯随机、敌我不分，无专属寻路件——届时复用哨兵 StateTree + 随机可达点漫游即可，按 §五微调。

# 二、总体架构

```
        ┌ 感知层 AIPerception（视觉/听觉/噪音事件）──────────────── 只产数据，不参与寻路
        │
地面怪 ─┤ StateTree 资产变量 + Context Actor（共享状态：目标 / 巡逻点 / 家坐标）
        │ StateTree 状态机（哨兵、掠食者各一株；裁决者复用哨兵资产改三处）
        │
        └ 移动层：NavMesh(Recast 静态烘焙) → MoveTo → RVO 局部避让
                  ↑ AntiStuck 组件（全程旁听）→ 解卡状态（挪窝 / 相位位移）

蜂群（独立） SwarmHive 状态机 Idle ↔ Engage → Boids（分离/对齐/聚合）+ 直线追踪 + 射线避墙
审计官（独立） 状态机 Dormant → Harass → Execute → 移动复用同一套地面怪移动层
```

四条铁律（对应"防撞墙 / 防卡死 / 防互撞"三问 + 性能）：

1. **防撞墙**：Agent Radius 42 → NavMesh 生成时按半径内缩，路径中心线天然离墙 40cm+
2. **防卡死**：移动中每 0.5s 采样位置，累计 3s 无位移 → AntiStuck 组件置 bStuck → 转换进解卡状态
3. **防互撞**：RVO 分离（引擎自带）+ 攻击名额（§十）+ 密度表控总量（总量上限是最有效的避让）
4. **性能**：静态烘焙 NavMesh 运行时零重算成本；追击重规划 = 引擎 MoveTo 任务的 bTrackMovingGoal 自动追踪目标，不写轮询代码

# 三、工程配置（谁摆什么）

## 3.1 项目设置（一次配完）

| 位置 | 设置 | 值 | 为什么 |
| --- | --- | --- | --- |
| Project Settings → Navigation Mesh | Runtime Generation | **Static** | 三区地图静态，运行时不重烘焙，零开销 |
| 同上 | Agent Radius | **42**（哨兵胶囊 35 + 余量） | 内缩量 = 防撞墙第一道防线 |
| 同上 | Agent Height / Max Walkable Angle | 180 / 40° | 匹配机械守卫体型 |
| Project Settings → Navigation System | Auto Create Navigation Data | 开（默认） | 无需手动放 NavMesh 实例 |

> Runtime Generation 选项位置随 UE5 小版本在 Navigation System 与 RecastNavMesh 类默认值之间挪动，认准值本身。

## 3.2 关卡摆放（子关卡归属，铁规矩）

| 内容 | 放哪 | 谁摆 |
| --- | --- | --- |
| NavMeshBoundsVolume（覆盖全区地面） | _Structure | 区主理人（A 区 C / B 区 D / C 区组长） |
| 哨兵巡逻点（引擎自带 TargetPoint，拖即用） | _Gameplay | 毛泽涛建区、唐瑀含按密度表摆点 |
| 刷怪点 SpawnActor / 蜂群 SwarmHive | _Gameplay | 同上 |
| E2 货梯等移动物件 | _Structure | **关掉 Can Ever Affect Navigation**（AI 不应走竖井，也避免运行时重烘焙） |

验收方式：摆完按 **P** 重建，绿网必须连续覆盖每条走廊；门洞净宽 **≥ 1.5m**（两台哨兵错身 + RVO 摆动余量）。**墙体碰撞预设保持默认（StaticMesh → WorldStatic 通道），禁止改设 WorldDynamic/自定义通道**——蜂群 sweep 移动只对 WorldStatic 做 Block 判定，墙换通道 = 无人机穿墙。门洞、走廊这类瓶颈点在灰盒阶段就要按此检查，比事后修 AI 划算得多。

## 3.3 AIController（哨兵 / 掠食者 / 审计官共用 C++ 基类，已落地）

- **C++ 基类 `ACyberEnemyAIController` 已提供**（Source/CyberRuin，编译验证通过）：默认挂 **StateTreeAIComponent** 并接入 AIC 的 Brain 槽——引擎在 Possess 流程自动启停，与旧 BT 同生命周期；RVO 已预配：**分离开启 + Medium 避让质量 + 分离权重 1.0**
- 派生 BP 只需两步：细节面板指定 **EnemyStateTree** 资产 → 怪 BP 的 AIController Class 选它
- RVO Priority（体型大者优先，小的让路）：审计官 > 裁决者 > 掠食者 > 哨兵——在各怪 BP 的 AIC 上调
- MoveTo：直接用**引擎自带任务 Move To（FStateTreeMoveToTask，GameplayStateTree 插件）**——AcceptableRadius 追击 120 / 巡逻 60；**`bTrackMovingGoal = true` 自带移动目标路径追踪**（等效旧 BT 观察者中止的自动重规划，无需自写重发）
- 过场接口：`FreezeLogic()` / `UnfreezeLogic()`（Pause 保留状态 + 停移动），供过场动画冻结/恢复全场怪
- 感知 → 状态切换：AIC 的 `OnTargetPerceptionUpdated` 蓝图事件里 `Send State Tree Event`（Tag 如 `Event.Enemy.Seen` / `Event.Enemy.Lost`），转换条件选"收到事件"，不写轮询

## 3.4 墙体与布局硬性要求（预判 + 可直接发给建区 AI 的清单）

**预判**：建区大概率也是 AI 主导。仓库现状（2026-10-04）：六分支全空、唯一地图为模板 Lvl_ThirdPerson（World Partition + OFPA）、Content/LevelPrototyping 灰盒件齐全、启用了 ModelingToolsEditorMode。由此预判：

| 概率 | 建区 AI 的路线 | 产物 |
| --- | --- | --- |
| 最可能（>85%） | LevelPrototyping 灰盒件（SM_Cube 等 StaticMeshActor）缩放旋转拉墙 | 带默认碰撞的 StaticMesh |
| 次可能 | Modeling 工具建墙再烘焙成静态网格 | 同上（StaticMesh） |
| 小概率 | BSP Brush / PCG 程序化 | Brush 碰撞特殊、PCG 调试成本高，学生项目不会当主力 |

三条路产物殊途同归（StaticMesh + 默认碰撞），因此**要求只约束最终形态，不限实现方式**。

**墙体硬性要求（验收只看结果）**：

| # | 要求 | 原因 | 验收 |
| --- | --- | --- | --- |
| W1 | 墙体 = 静态碰撞几何，Object Type = WorldStatic、碰撞预设保持默认（BlockAll） | 蜂群 sweep 防穿墙只 Block WorldStatic（§七）；NavMesh 按碰撞体烘焙 | 选中墙 → StaticMesh 设置里查 Collision Presets |
| W2 | 禁止把墙改成 QueryOnly / NoCollision / 自定义通道 | 改了 = 无人机穿墙 / 绿网穿帮 | 同上 |
| W3 | 装饰小件（管线、贴花、灯具、桌椅）NoCollision，或关 Can Ever Affect Navigation | 碎碰撞会把 NavMesh 烘出窟窿、卡巡逻路线 | 按 P 后绿网连续无断裂 |
| W4 | 视觉与碰撞一致：没有"看得见走不进"的假墙，也没有隐形碰撞体 | 玩家手感与 AI 寻路共用同一套世界 | 目测 + 走位试 |

**布局硬性要求（AI 拉房间时直接照抄的数字）**：

| 参数 | 数值 | 原因 |
| --- | --- | --- |
| 走廊净宽 | ≥ 300cm | 两台哨兵错身 + RVO 摆动余量 |
| 门洞净宽 | ≥ 150cm | 同上（瓶颈点，最容易出卡怪） |
| 室内净高 | ≥ 300cm | Agent Height 180 + 蜂群悬停层 150 |
| 可走斜坡 | ≤ 40° | 与 NavMesh Agent Max Walkable Angle 对齐（§3.1） |
| 死缝/凹槽 | 宽度 < 100cm 的缝一律填掉 | 窄缝会被烘进绿网，成为卡怪死角 |
| E2 货梯等活动件 | Can Ever Affect Navigation = false | 运行时移动件不参与绿网 |
| B 区保险库门口 | 5m×5m 战斗平台 + 30m 追击圈绿网覆盖 | 裁决者战斗平台（§八） |
| 撤离平台 E1 | 落点必须在绿网上 | 撤离窗口守卫活性 +50%，怪要围得过来 |

# 四、防卡死：检测组件 + 解卡兜底（全怪共用）

### AntiStuckComponent.h / .cpp

```cpp
// AntiStuckComponent.h
#pragma once

#include "Components/ActorComponent.h"
#include "AntiStuckComponent.generated.h"

/**
 * 卡死检测组件（全怪共用，框架无关）：每 0.5s 采样一次位置，
 * 仅在"正在移动"时累计——位移持续低于阈值 → bStuck = true。
 * 为什么用组件而不是 StateTree 任务：蜂群不走 StateTree、审计官走自建状态机，
 * 组件三者通吃；StateTree 只在转换条件里读 bStuck，审计官状态机直接读。
 * 挂在怪 BP 上（BP_BaseEnemy 默认添加）。
 */
UCLASS(ClassGroup = (赛博遗迹AI), Meta = (BlueprintSpawnableComponent))
class CYBERRELIC_API UAntiStuckComponent : public UActorComponent
{
    GENERATED_BODY()

public:
    UAntiStuckComponent();

    virtual void TickComponent(float DeltaTime, ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction) override;

    /** 卡死判定结果：StateTree 转换条件 / 审计官状态机直接读 */
    UPROPERTY(BlueprintReadOnly, Category = "AntiStuck")
    bool bStuck = false;

    /** 每采样周期要求的最小位移(cm)，低于即记作"没动"。慢速怪(如裁决者)可调低 */
    UPROPERTY(EditAnywhere, Category = "AntiStuck")
    float MinMovePerSample = 10.f;

    /** 连续"没动"多久判定卡死 */
    UPROPERTY(EditAnywhere, Category = "AntiStuck")
    float MaxStuckSeconds = 3.f;

private:
    FVector LastLocation = FVector::ZeroVector;
    float StuckTime = 0.f;
};
```

```cpp
// AntiStuckComponent.cpp
#include "AntiStuckComponent.h"
#include "AIController.h"
#include "GameFramework/Pawn.h"
#include "Navigation/PathFollowingComponent.h"

UAntiStuckComponent::UAntiStuckComponent()
{
    PrimaryComponentTick.bCanEverTick = true;
    PrimaryComponentTick.TickInterval = 0.5f; // 采样频率 = tick 频率，编辑器里可调
}

void UAntiStuckComponent::TickComponent(float DeltaTime, ELevelTick TickType, FActorComponentTickFunction* ThisTickFunction)
{
    Super::TickComponent(DeltaTime, TickType, ThisTickFunction);

    const APawn* Pawn = Cast<APawn>(GetOwner());
    AAIController* AI = Pawn ? Cast<AAIController>(Pawn->GetController()) : nullptr;

    // 只在移动中计时：待机/攻击原地不动不算卡死
    const bool bMoving = AI && AI->GetPathFollowingComponent()
        && AI->GetPathFollowingComponent()->GetStatus() == EPathFollowingStatus::Moving;
    if (!bMoving)
    {
        StuckTime = 0.f;
        bStuck = false;
        return;
    }

    const FVector Current = Pawn->GetActorLocation();
    const float MovedCm = FVector::Dist2D(Current, LastLocation);
    LastLocation = Current;

    StuckTime = (MovedCm < MinMovePerSample) ? StuckTime + DeltaTime : 0.f;
    bStuck = StuckTime >= MaxStuckSeconds;
}
```

```cpp
// CyberAIFunctionLibrary.cpp
#include "CyberAIFunctionLibrary.h"
#include "NavigationSystem.h"
#include "GameFramework/Actor.h"

static UNavigationSystemV1* GetNav(const UObject* Ctx)
{
    const UWorld* World = Ctx ? Ctx->GetWorld() : nullptr;
    return World ? FNavigationSystem::GetCurrent<UNavigationSystemV1>(World) : nullptr;
}

bool UCyberAIFunctionLibrary::WarpToNearestNavigable(AActor* Actor, float SearchRadius)
{
    UNavigationSystemV1* NavSys = GetNav(Actor);
    if (!Actor || !NavSys)
    {
        return false;
    }

    const FVector From = Actor->GetActorLocation();
    FNavLocation Out;

    // 先试原地投影（多数卡死只差一步），失败再随机找近旁可达点
    if (NavSys->ProjectPointToNavigation(From, Out) ||
        NavSys->GetRandomPointInNavigableRadius(From, SearchRadius, Out))
    {
        return Actor->TeleportTo(Out.Location, Actor->GetActorRotation());
    }
    return false;
}

bool UCyberAIFunctionLibrary::ValidateSpawnPoint(const UObject* WorldContextObject, const FVector& Desired, FVector& OutSpawn)
{
    UNavigationSystemV1* NavSys = GetNav(WorldContextObject);
    if (!NavSys)
    {
        return false;
    }

    FNavLocation Out;
    if (NavSys->ProjectPointToNavigation(Desired, Out))
    {
        OutSpawn = Out.Location;
        return true;
    }

    UE_LOG(LogTemp, Warning, TEXT("[AI] 刷怪点不在导航网格上: %s"), *Desired.ToString());
    return false; // 调用方（SpawnDirector）跳过本次刷怪
}
```

**StateTree 接入**（见 §十一 状态图）：所有状态的转换表加一条 **AntiStuck->bStuck == true → 解卡状态**（优先级排最高，等价 BT 的高优先级中断分支）；解卡状态任务 = 调 WarpToNearestNavigable → 回巡逻/回岗。
**审计官接入**：状态机每帧直接读 `AntiStuck->bStuck`，与 §四 完全同一套逻辑。
**预期频次：10 局不超过 1 次**。日志里出现 = 某个巡逻点/地形有问题，按坐标找区主理人修地形，而不是加更多兜底代码。

```cpp
void UPatrolRouteComponent::Advance()
{
    if (Points.Num() == 0)
    {
        return;
    }

    if (bPingPong && Points.Num() > 1)
    {
        // 两端折返时跳过刚走过的端点，避免原地空走一次
        if (bGoingUp)
        {
            (Index + 1 < Points.Num()) ? ++Index : (bGoingUp = false, Index = FMath::Max(0, Index - 1));
        }
        else
        {
            (Index - 1 >= 0) ? --Index : (bGoingUp = true, Index = FMath::Min(Points.Num() - 1, Index + 1));
        }
    }
    else
    {
        Index = (Index + 1) % Points.Num();
    }
}
```

### 巡逻状态（StateTree，无 C++ 任务）

巡逻状态的 **BP 任务**三步：`GetCurrentPoint` → 把点写进 StateTree 资产变量 `PatrolPoint` → MoveTo 类任务走向该点；到达（或失败）后任务里调 `Advance()` 排好下一个点。MoveTo 失败时下一轮自动跳过坏点，巡逻路线自愈。哨兵状态结构见 §十一。

```cpp
// CyberAIFunctionLibrary.cpp 追加
bool UCyberAIFunctionLibrary::GetFlankPoint(const AActor* Target, float FlankDistance, float SampleArcDegrees, FVector& OutPoint)
{
    UNavigationSystemV1* NavSys = GetNav(Target);
    if (!Target || !NavSys)
    {
        return false;
    }

    // 玩家背后扇形上均匀取 7 个候选，投影到导航网格，取第一个成功的（背后死角优先）
    const FVector PlayerLoc = Target->GetActorLocation();
    const FVector Facing = Target->GetActorForwardVector().GetSafeNormal2D();

    for (int32 i = 0; i < 7; ++i)
    {
        const float Deg = 180.f - SampleArcDegrees + (2.f * SampleArcDegrees / 6.f) * i;
        const FVector Candidate = PlayerLoc + Facing.RotateAngleAxis(Deg, FVector::UpVector).GetSafeNormal2D() * FlankDistance;

        FNavLocation Out;
        if (NavSys->ProjectPointToNavigation(Candidate, Out))
        {
            OutPoint = Out.Location;
            return true;
        }
    }
    return false;
}
```

为什么不用 EQS：单点生成逻辑，一个库函数比一张 EQS 资产直观，少一层调试。

状态流程（完整状态图见 §十一）：取绕后点 → `MoveToLocation(FlankPoint, Acceptance 160)` → 到点后如仍处于玩家背后 90° 扇形 → 触发背刺事件（蓝图/Gameplay 层，不属寻路）。全程速度压到玩家的 70%（420 vs 600），静音接近靠"慢"而不是魔法。

# 七、蜂群：蜂群算法，不走导航

蜂群是**飞行群体单位**：走 NavMesh 既贵（3D 寻路）又不必要。整群 = 1 个 Hive（导演）+ N 个无人机（纯被驱动的壳）。

- **封锁行为**：Idle 状态绕锚点（摆放位置）盘旋；玩家站着/跑着进入 GuardRadius → Engage 向玩家头顶聚拢
- **断视线可甩**：锚点→玩家射线被墙挡住 → 整群回锚点。蜂群封的是区域不是人——躲墙断视线是给玩家的战术解，绕路成本留给地面怪
- **蹲行可穿 = 对蜂群"失明"**：蹲行玩家完全不触发 Engage（不做碰撞变化，行为层解决）
- **防穿墙 = sweep 硬保证**：移动用 `SetActorLocation(…, true)` 连续碰撞检测，撞墙即停、贴墙滑动（依赖 §3.2 墙体通道铁律）；避墙射线只是顺滑层，失效也穿不透
- **EMP 清组**：`ClearByEMP()` 一次性全灭，爆点委托给 D 的粒子
- **性能**：n≤32 朴素 O(n²) 每帧 <1000 次向量运算 + 每帧 1 条锚点视线射线，Hive 30Hz；个体无人机零 Tick

```cpp
void ASwarmHive::Tick(float Dt)

    Super::Tick(Dt);

    const ACharacter* Player = UGameplayStatics::GetPlayerCharacter(this, 0);
    const bool bCrouched = Player && Player->GetCharacterMovement() && Player->GetCharacterMovement()->IsCrouching();
    const bool bInZone = Player && FVector::Dist2D(Player->GetActorLocation(), Anchor) <= GuardRadius;
    const bool bAlerted = GetWorld()->TimeSeconds < AlertedUntil;

    // 蜂群封的是区域不是人，躲墙断视线成为玩家的战术解，绕路成本留给地面怪。
    bool bAnchorLOS = false;

    const FVector Target = (bEngage && Player)
        ? Player->GetActorLocation() + FVector(0.f, 0.f, 160.f) // 悬在头顶一圈
        : Anchor + FVector(0.f, 0.f, HoverZ);

    SteerAll(Dt, Target, bEngage ? EngageSpeed : IdleSpeed);
}

void ASwarmHive::SteerAll(float Dt, const FVector& Target, float Speed)
{
    for (ASwarmDrone* Drone : Drones)
    {
        if (!Drone)
        {
            continue;
        }

        // ---- Boids 三规则（群内两两比较，n≤32 时 O(n²) 完全够用）----
        FVector Sep = FVector::ZeroVector, Align = FVector::ZeroVector, Center = FVector::ZeroVector;
        int32 Neighbors = 0;

        for (ASwarmDrone* Other : Drones)
        {
            if (!Other || Other == Drone)
            {
                continue;
            }
            const FVector Diff = Drone->GetActorLocation() - Other->GetActorLocation();
            const float Dist = Diff.Size();
            if (Dist < SeparationRadius && Dist > 1.f)
            {
                Sep += Diff / Dist * (SeparationRadius - Dist) / SeparationRadius; // 越近推得越狠
                Align += Other->Vel;
                Center += Other->GetActorLocation();
                ++Neighbors;
            }
        }

        FVector Steer = (Target - Drone->GetActorLocation()).GetSafeNormal();
        if (Neighbors > 0)
        {
            Steer += Sep.GetSafeNormal() * 1.6f;                                           // 分离权重最高
            Steer += (Align / Neighbors - Drone->Vel).GetSafeNormal() * 0.4f;              // 对齐
            Steer += (Center / Neighbors - Drone->GetActorLocation()).GetSafeNormal() * 0.5f; // 聚合
        }

        // ---- 避墙射线：提前转向的"顺滑层"；防穿墙的硬保证在下方 sweep 移动 ----
        FHitResult Hit;
        const FVector TraceEnd = Drone->GetActorLocation() + Drone->Vel.GetSafeNormal() * WallLookAhead;
        if (GetWorld()->LineTraceSingleByChannel(Hit, Drone->GetActorLocation(), TraceEnd, ECC_Visibility)
            && Hit.Normal.Z < 0.7f) // 忽略地面/坡面，只躲竖直墙
        {
            Steer += Hit.Normal.GetSafeNormal2D() * 2.5f;
        }

        Drone->Vel = (Drone->Vel + Steer * Dt * 900.f).GetClampedToMaxSize(Speed);

        // sweep 移动是防穿墙硬保证：撞上即停在墙面（依赖墙在 WorldStatic 通道，见 §3.2）
        FHitResult MoveHit;
        const FVector NewLoc = Drone->GetActorLocation() + Drone->Vel * Dt;
        if (!Drone->SetActorLocation(NewLoc, true, &MoveHit) && MoveHit.IsValidBlockingHit())
        {
            // 贴墙滑动：速度投影到墙面切线继续走 + 轻微离墙推力，避免"趴墙抖动"
            Drone->Vel = FVector::VectorPlaneProject(Drone->Vel, MoveHit.Normal) + MoveHit.Normal * 50.f;
        }
    }
}
```

```cpp
// AttackSlotSubsystem.cpp
#include "AttackSlotSubsystem.h"
#include "UObject/ObjectKey.h"
#include "GameFramework/Actor.h"

UAttackSlotSubsystem* UAttackSlotSubsystem::Get(const AActor* Actor)
{
    const UWorld* World = Actor ? Actor->GetWorld() : nullptr;
    return World ? const_cast<UWorld*>(World)->GetSubsystem<UAttackSlotSubsystem>() : nullptr;
}

bool UAttackSlotSubsystem::TryAcquireSlot(AActor* Attacker, AActor* Target, FVector& OutPoint)
{
    if (!Attacker || !Target)
    {
        return false;
    }

    const float SectorDeg = 360.f / NumSlots;
    // 攻击者相对目标的角度 → 离它最近的扇区编号
    const FVector Dir = (Attacker->GetActorLocation() - Target->GetActorLocation()).GetSafeNormal2D();
    const int32 Wanted = ((FMath::RoundToInt(FMath::RadiansToDegrees(FMath::Atan2(Dir.Y, Dir.X)) / SectorDeg)) + NumSlots) % NumSlots;

    TSet<int32> Taken;
    for (const TPair<FObjectKey, int32>& Pair : Claimed)
    {
        Taken.Add(Pair.Value);
    }

    int32 Best = -1;
    float BestCost = FLT_MAX;
    for (int32 i = 0; i < NumSlots; ++i)
    {
        if (Taken.Contains(i))
        {
            continue;
        }
        const int32 Offset = (i - Wanted + NumSlots) % NumSlots;
        const float Cost = FMath::Min(Offset, NumSlots - Offset) * SectorDeg; // 角度距离
        if (Cost < BestCost)
        {
            BestCost = Cost;
            Best = i;
        }
    }

    if (Best < 0)
    {
        return false;
    }

    Claimed.Add(FObjectKey(Attacker), Best);
    const float Angle = FMath::DegreesToRadians(Best * SectorDeg);
    OutPoint = Target->GetActorLocation() + FVector(FMath::Cos(Angle), FMath::Sin(Angle), 0.f) * RingRadius;
    return true;
}

void UAttackSlotSubsystem::Release(AActor* Attacker)
{
    Claimed.Remove(FObjectKey(Attacker));
}
```

# 十一、StateTree 速查（哨兵 / 掠食者 / 裁决者）

## 11.0 落地要点（先读这个）

| 要点 | 做法 |
| --- | --- |
| 运行组件 | **C++ 基类 ACyberEnemyAIController 已挂好 StateTreeAIComponent（Brain 槽，引擎自动启停）**；派生 BP 只需指定资产（ST_Sentinel / ST_Predator / ST_Arbiter） |
| 变量（替代黑板） | 资产内变量见 11.1；组件直读：AntiStuck->bStuck |
| 感知 → 状态 | AIC 的 `OnTargetPerceptionUpdated` 蓝图里 **Send State Tree Event**（Tag：Event.Enemy.Seen / Event.Enemy.Lost），转换条件选"收到事件"；同时每 0.5s 写一次 TargetLocation 变量 |
| 读组件条件 | 转换条件用 BP 条件：Context Actor → FindComponentByClass\<AntiStuckComponent\> → bStuck |
| MoveTo 任务 | **直接用引擎任务 Move To（FStateTreeMoveToTask，零自研）**：TargetActor / Destination / AcceptableRadius，`bTrackMovingGoal=true` 自带移动目标追踪重规划 |
| C++/BP 分工 | 数学与导航全在 C++ 函数库和组件（§四~§六）；StateTree 任务层全部 BP，只做"取值 → 调库 → 写变量" |
| 完成语义 | 任务返回 Succeeded/Failed/Running 驱动状态内流程；转换表驱动状态切换 |
